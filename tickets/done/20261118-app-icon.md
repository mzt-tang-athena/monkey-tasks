## Spec

The app ships with the Expo starter icon: a blue "A" over guide
circles. It says nothing about this app. The operator picked a new icon
on 2026-11-18. The design is a flat matcha square, `#7A9A3E`, with one
bold white tick.

`docs/adr/20261118-app-icon.md` records the pick and its rejected
concepts.

Every icon asset must come from a committed source. A colour or a
shape change is then one edit and one command. The adaptive icon must
survive the Pixel circle mask, and themed icons must show the tick. The
emulator proves the result.

## Acceptance

- [x] `app/scripts/app-icon/source/` holds the SVG sources.
- [x] `npm run app-icon:build` rebuilds every asset.
- [x] `icon.png` is 1024 square, opaque and full bleed.
- [x] The adaptive tick fits the 66 of 108 safe circle.
- [x] `adaptiveIcon.backgroundColor` is `#7A9A3E`.
- [x] A test fails when a source and `app.json` drift apart.
- [x] The local gate passes.
- [x] The emulator shows the icon on the home screen.
- [x] The emulator shows the icon in the app drawer.
- [x] Themed icons show the tick, with themed icons on.
- [x] The ADR records the pick and the rejected concepts.

## Outcome

The app shows a flat matcha tile with a white tick.

- Sources: `app/scripts/app-icon/source/`, four SVGs.
- `npm run app-icon:build` writes six PNGs and the preview.
- `adaptiveIcon.backgroundColor` is `#7A9A3E`.
- A unit test guards the colour, the safe circle and sizes.
- ADR `20261118-app-icon` records the pick and rejects.

The release APK ran on the Pixel 7 emulator, API 35. The icon showed
on the home screen and in the app drawer. With Themed icons on, the
monochrome tick took the system tint. `aapt2` shows all three adaptive
layers in the APK.

Gate: tsc, eslint, 1169 tests in 120 files, Vale and record names.
No app code changed, so the web suite did not run.

Screenshots are in the PR and in `docs/assets/`.
